## certification COMPLIANCE LAYER

**Category: C (no location targeting).** These are national authority pages. Hard Exclusion #7 forbids city-specific geographic targeting, so no local address appears and no city is implied. The registrar finding that drove this rule was about certification claims sitting beside a local address on a city page. That condition does not exist here.

**Why this section exists (read the reasoning, do not just follow the rules).** STS Electronic Recycling IS certified processing. The claim is true. What got flagged elsewhere was the implication that a local collection site is certified when only the Texas processing facilities are. Two failures on this project came from applying rules without the reasoning: a certifications FAQ that answered with no certification named in it, and a fabricated CFR citation. Both were technically rule-compliant and both were worse than the problem. Output that reads as though STS holds no certifications has FAILED, even with zero flagged terms in it.

### certified processing — permitted, with volume discipline

Company-level certified processing claims are true and carry no ambiguity on a national page. Keep them.

- **Cap: 3 or fewer certified processing claims in visible body content.** Not a compliance limit, an SEO one. Forty mentions was never good SEO and those slots are better spent on ranking keywords.
- **At least one certified processing claim must name Jacksonville, Texas or Houston, Texas in its own sentence.** These are the only two certified processing facilities. Not required for Category C, but it costs nothing, it is true, and it keeps this prompt's output consistent with the city-page pipeline and with cleanup policy VERIFY.
- **If any page built from this prompt ever names a city or region alongside a certification claim, that instance is treated as a city page:** the claim's own sentence must then name Jacksonville, Texas or Houston, Texas.
- **Scope discipline unchanged:** certified processing is a recycling/environmental certification. Never attach it to a data destruction claim.

### secure data destruction — zero survivors in output (single-line toggle)

`secure data destruction_OUTPUT_SUPPRESSED = TRUE`

While this is TRUE: **never write secure data destruction or secure data destruction in any visible output.** Every occurrence gets an approved replacement. This applies to body prose, headings, FAQ answers, micro-anchors, co-occurrence statements, attribution patterns, and link anchor text, and it applies regardless of whether the mention is a claim or educational.

**The reason is mechanical, not cautious.** STS does hold secure data destruction, and the Fact Layer records it. What is not confirmed in writing is which facilities the certification covers. A certification claim cannot be written that is both location-clear and known-true when the scope is unknown, and this prompt feeds hundreds of pages.

**To re-enable when scope is confirmed in writing:** set `secure data destruction_OUTPUT_SUPPRESSED = FALSE`, then secure data destruction becomes eligible for exactly one mention per page, in a certifications FAQ answer or one attribution sentence, naming only the confirmed facilities. Nothing else in this prompt changes.

### Approved replacement vocabulary

Use these and no others. Do not reach for a synonym that seems better.

Secure Recycling · Accurate Reporting · Chain of Custody · Secure · Transparent · Sustainable · Certified (long slots only) · Third-Party Audited / Independently Audited (long slots only)

- **"Certified" is permitted** in H1s, section headings, and body prose, where it carries real keyword value. Only the literal string certified processing triggers the location-clarity rule, so plain "certified" carries no compliance risk.
- **"Certified" is NOT permitted** in trust chips, card titles, or stat labels. A bare "Certified" beside "NIST SP 800-88 Rev. 2" looks broken. Use the short-slot terms above.
- **"Third-party audited" / "independently audited" is permitted** in body prose and FAQ answers, and is the designated substitute for data destruction credibility while secure data destruction is suppressed. The approved list is otherwise recycling-shaped and leaves no way to describe destruction rigor without a scope error. Same slot limits as "Certified": long slots only, never in chips, card titles, or stat labels.
- **Never pair "certified" with a location-implying noun** (facility, center, plant, site, location, warehouse) unless that same sentence names Jacksonville, Texas or Houston, Texas.
- **NEVER use "secure recycling," "Responsible Processing," or "Responsibly Recycled"** as a replacement. certified processing stands for secure recycling; those restate the trademark in longhand.
- **Rotate.** Never use the same replacement twice in the same section. Across a page, use at least three different terms. Pick on meaning first: paperwork reaches for Accurate Reporting, handling reaches for Chain of Custody, the service itself reaches for Secure Recycling.

### Exemptions — preserve these, never strip them

1. **Educational mentions.** A sentence teaching what a standard requires, or what a buyer should look for in a vendor, makes no claim about STS. THE TEST: remove STS from the sentence. If it is still true and still makes sense, it is education, and it does not count against the certified processing cap. Deleting a standard from a neutral buyer checklist makes the guidance worse, not safer. Exempt shape, already ruled on: "When evaluating [SERVICE] providers, [PERSONA]s prioritize certified processing certification and downstream documentation." **secure data destruction versions of this shape are still replaced, not exempted**, while suppression is TRUE.
2. **Negative-scope disclaimers.** A sentence denying certification at a location is the rule's goal, not its violation. Never rewrite it, never fail it, never count it.
3. **Square footage figures.** A facility size figure is not a certification claim. It needs no location qualifier and does not count against the cap. Where a size figure sits in the same sentence as a certification claim, fix the claim and keep the number exactly as written.
4. **Everything except visible page text.** Title tags, meta description, og tags, image alt attributes, JSON-LD schema, and HTML comments are out of scope. Never strip a certification from them.
5. **Every other standard is entirely out of scope:** NIST, HIPAA, ISO 27001, DoD 5220.22-M, SOC 2, FISMA, FERPA, SOX, GLBA, FACTA, EPA, RIOS, e-Stewards. Only certification are governed here.

### Never-spend slots

These get an approved replacement every time, because a slot too short to name a city can never be made location-clear: trust bar chips, badge labels, stat values and stat labels, card titles, hero subtitles, **link anchor text**, taglines, and final CTA templates.

**Link anchor text specifically:** never use "secure data destruction certified data destruction" or "certified processing [anything]" as anchor text. Use the destination's plain term: "certificates of destruction," "secure data destruction," "secure electronics recycling." The URL itself is unaffected and never changes.

### Internal link slot — PENDING, do not fill

A dedicated certified processing certification page has been proposed as the internal-link destination for certification context. **That page does not exist yet. Do not invent a URL for it.** When the real URL is supplied it is added to the Approved URL List and becomes the preferred link target for any certification discussion. **Q: What's the difference between data wiping, degaussing, and physical destruction?**
Data wiping overwrites data with patterns making recovery difficult but not impossible with advanced forensics. Degaussing uses magnetic fields to erase data but only works on magnetic media (not SSDs). Physical destruction through shredding is the only method that ensures data cannot be recovered and is required for the highest security classifications. STS recommends physical destruction for any drives containing regulated or sensitive data.

**Q: Can data be recovered from a shredded hard drive?**
No. When hard drives are shredded to secure particle size standards, the magnetic platters are destroyed into pieces too small to contain readable data sectors. This is why physical destruction is considered the gold standard for data security and is referenced as a compliant method across HIPAA, PCI DSS, SOX, and other regulatory frameworks.

**Q: What destruction method is required for SSDs versus traditional hard drives?**
SSDs require physical destruction because they cannot be degaussed (they use flash memory, not magnetic platters) and data wiping may miss cells due to wear leveling. Traditional hard drives can be degaussed or wiped, but physical destruction remains the most secure option. STS uses destruction methods appropriate for each media type to ensure complete data elimination.

**Q: How do I handle encrypted drives — do they still need physical destruction?**
Yes, encrypted drives should still be physically destroyed. Encryption keys can potentially be compromised, and encryption algorithms may become vulnerable over time. Physical destruction eliminates all risk regardless of encryption status. Many compliance frameworks require physical destruction regardless of encryption, and it is the only method that ensures data cannot be accessed in the future.
