## The problem with the current documentation

The documentation exists, but it has three weaknesses:

1. **It is scattered.**  
   The visual style is in the master prompt and existing image manifest. The execution gate is in memory. The provider requirement was not consistently defined.

2. **The master prompt says “Gemini” while the project also uses OpenAI.**  
   That creates provider confusion. It needs one canonical provider instruction.

3. **The prompt’s quality gate was not strong enough in practice.**  
   It says to check realism, but it also previously said to ship the best available result after a failed retry. That allows a technically compliant but ugly image to pass. The prompt needs to explicitly reject generic AI still lifes, plastic objects, repetitive arrangements, and images that weaken the design.

There is also some inconsistency in the existing manifest. For example, several older image records mention visible serialized labels or certificate text, while the newer master prompt says there must be no rendered text of any kind. The newer rule should take precedence.

## Bottom line

We already have documentation saying the images should not look AI-generated. The most useful existing references are:

- `...UNIVERSAL-MASTER-PAGE-BUILDER-SOURCE-OF-TRUTH-v1-4...txt`
- `artifacts/data2shred/public/images/MANIFEST.md`
- `.agents/memory/mandatory-image-generation.md`

What we do not yet have is one authoritative project document that combines:

- OpenAI as the required provider
- The documentary photography style
- The anti-AI visual-quality gate
- Hero-background composition rules
- The rejection criteria
- The actual execution and verification requirements

That is the documentation gap that caused the benchmark process to technically pass while producing images you correctly identified as fake and ugly.
