## PART 1 vs PART 2 SPLIT Analysis

The precise split for automation logic resides right between **Menu Link Provisioning** and **Content Creation**.

* **PART 1 (Page/Meta Setup):** Covers Steps 1-6. This configures the system routing path, access groups, template design overrides, menu parent tree categorization, and browser display indicators.
* **PART 2 (HTML & Schema Content):** Covers Steps 7-11. This interacts directly with the database's content schema arrays, handling HTML strings, dynamic module injections, and JSON-LD structured data block generation.
* **Can Part 1 be completed before the HTML file exists?**
**No.** Joomla's database structural constraints require a `Single Article` menu node to contain a valid, existing `id` mapping reference within the `j_content` table before saving.
* *The Correct Automation Sequence:* The browser agent must execute a **Three-Step Pass**:
1. **Pass 0:** Create the Article object shell (giving it the correct city title), save it, and scrape its generated `Article ID` or edit link window context.
2. **Pass 1 (Part 1 Setup):** Create the Menu item node, link it directly to the freshly created `Article ID`, set up aliases/templates, and save.
3. **Pass 2 (Part 2 Content):** Open the article editor interface, toggle to code view, insert HTML content strings, attach the Google Structured Data components, save, and then wipe the cache clear via `com_cache` (Part 3).

## GOTCHAS (Automation Script Vulnerabilities)

1. **The Modal Frame Context Trap:** Clicking `[ Edit ]` under the article section invokes an inline iframe container overlay. An automated browser execution script (e.g., Playwright/Selenium) will completely stall unless it is programmed to detect the frame load event and explicitly steer its driver execution context inside the sub-frame element.
2. **Editor State Persistence:** The `Toggle Editor` setting retains its text-view/WYSIWYG layout preference globally across a single logged-in user profile session. If a previous task left the editor in plain WYSIWYG view, clicking the text box blindly treats the payload as raw text instead of code. The automation script must first read the editor element properties to decide if clicking `Toggle Editor` is necessary.
3. **Stale Cache Masking:** Because site-wide `page` cache allocations sit near **`26.71 MB`**, front-end assertions checking for successful automated updates will routinely return false negatives unless the automation block systematically runs the cache purge macro inside `com_cache` right after publishing.
