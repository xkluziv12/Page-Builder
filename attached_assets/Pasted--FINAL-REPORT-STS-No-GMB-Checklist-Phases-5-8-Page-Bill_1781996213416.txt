## API RECOMMENDATIONS FOR REPLIT DASHBOARD

These three APIs should be integrated into the Replit QC dashboard and run as the final step after each city deployment — not through the task agent.

**1. GTmetrix API** *(you already have this)*
What it checks: Page speed, Core Web Vitals (LCP, TBT, CLS), performance score, waterfall
Endpoint: `POST https://gtmetrix.com/api/2.0/tests`
Key outputs to surface on dashboard: Performance score, Structure score, LCP, TBT, CLS, Time to First Byte, fully loaded time
Trigger: After Phase 8 cache clear — run against the live city URL

**2. Google Rich Results Test API** *(via Google Search Console API)*
What it checks: Valid structured data types, non-critical and critical schema issues
Endpoint: `https://searchconsole.googleapis.com/v1/urlTestingTools/richResultsTest:run`
Auth: Google OAuth2 / service account
Key outputs: List of detected types, error count per type, warning details
Note: Same as what we ran manually today — automating it removes the manual step entirely

**3. Schema Duplicate Detector** — recommended third-party: **Lipperhey** or **ScreamingFrog API** (or a custom Replit script)
What it checks: Parses the live page HTML, extracts all `<script type="application/ld+json">` blocks, checks for duplicate `@type` entries (e.g. two LocalBusiness blocks), conflicting `@id` values, and malformed JSON
Why it matters: Google and Schema.org validators don't flag duplicates as errors — but duplicate schema blocks can cause Google to ignore one or both. A custom Replit script using `cheerio` + `ajv` (JSON schema validator) can catch this in under 1 second per URL
Endpoint: Custom — fetch live URL → parse JSON-LD blocks → cross-check `@type` and `@id` uniqueness

**Recommended dashboard flow per city:**
1. GTmetrix test → flag if performance score < 85 or LCP > 2.5s
2. Google Rich Results API → flag any errors (orange warnings are acceptable, red errors are not)
3. Custom JSON-LD duplicate checker → flag any duplicate `@type` blocks or invalid JSON

All three run against the live URL, results logged to a Replit dashboard table with city name, run date, and pass/fail per check.
